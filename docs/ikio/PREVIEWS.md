# Card preview pipeline

Run `npm ci`, `npx playwright install --with-deps chromium`, `npm run build`, `npm run preview:build`, then `npm run preview:generate`. Output: dist/previews/index.html, manifest.json and 88 PNG captures (eleven cards, two themes, two widths, normal/unavailable). The HTML embeds the actual compiled collection bundle and local fixture/icon code and opens independently. Cards make simulated service/history/Alarmo requests. Native HA components are locally represented, not a live HA installation.

Fixtures live in dev/previews/fixtures/collection.js. Keep clocks and history deterministic; never add real household data, remote images or service endpoints. Unexpected mock APIs fail. Capture readiness waits for fonts, card requests and frames. Screenshots exclude gallery controls. PR comparisons show before, after and difference images; changed pixels do not fail checks, browser errors/blank cards/overflow do.

`PREVIEW_SOURCE=/path/to/base PREVIEW_OUTPUT=dist/base-previews npm run preview:build` and the same environment with `npm run preview:generate` run the current harness against another checkout's compiled bundle. Then `node scripts/compare-previews.mjs dist/base-previews dist/previews`. Incompatible baselines currently fail visibly rather than silently produce an empty comparison.

Every PR and main push runs previews; this initial implementation deliberately runs even for documentation changes to retain a stable check. The job summary points to the downloadable previews-COMMIT artifact (30-day retention). PR jobs are read-only and do not deploy or comment. Merge candidates and base renders are separate checkouts; manifest SHA is the actual rendered checkout.

Before committing a version bump run `npm run preview:readme`. CI checks that the marked README section references the authoritative version. Old published tags and directories are never changed. HACS collection resource and card runtime remain unaffected.

For new unpublished main versions, release waits for preview checks and publishes the complete retained gh-pages tree with the new previews/VERSION directory. Existing version directories must have identical manifests/hashes for retries. Pages deployment and HTTP verification precede GitHub release publication. Already published collection versions skip Pages/release publication. If the website succeeds and release publication fails, retry the exact commit; changed content requires a new version. Release attachments remain empty.

Repository setup: enable GitHub Pages with source **GitHub Actions** in Settings → Pages. Allow the github-pages environment to deploy from main. Permit the workflow token contents:write, pages:write and id-token:write in the release job. The site is https://kpolyd.github.io/ha-ikio-cards/. Add the `previews` check to branch protection if merges must be blocked. Those repository settings are not configured by source files. Downloaded CI artifacts require GitHub access; permanent release previews are public.

Limitations: fixtures have normal/unavailable scenarios with mixed device states, variable history and zero/unknown traffic. Dedicated armed/countdown, paused vacuum and per-card scenario controls and broader interaction smoke tests are follow-up coverage; an offline gallery/light-toggle smoke check runs after capture; screenshots alone do not establish native HA behavior. Pinning Playwright pins its Chromium revision; Ubuntu runner system fonts may still differ across runner image updates. Inspect captures and their differences when updating tools. Preview artifacts contain code and should be opened only from trusted PRs.
